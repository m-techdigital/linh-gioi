# Runtime Asset Actionable Budget

Marker: `LGO_RUNTIME_ASSET_WEIGHT_ACTIONABLE_BUDGET_READY`

## Purpose

Runtime image budgets must be actionable, not just descriptive. Every role should have a file-size budget, a watch threshold, and a next action when the asset is near or over budget.

## Decision Rules

- `OK`: keep one source asset per role and reuse it through Unity import profiles.
- `WATCH`: do not add variants for that role until profile downscale, audited optimization, or a budget exception is documented.
- `OVER_BUDGET`: block new runtime usage until the asset is resized/compressed or the exception is explicitly recorded.

## Profile Strategy

- PC/Desktop may keep the largest role-safe texture when visual evidence benefits from detail.
- Tablet should prefer import-profile downscale before duplicate source files.
- Mobile should use the smallest maxTextureSize that remains sharp at the real display size.
- Do not make separate mobile/tablet folders unless build pipeline work proves source duplication is required.

## Current Watch Queue

The current report generated by `tools/report_lgo_runtime_asset_size_inventory.py` carries an `Action` column. Watch rows are the next optimization queue before adding large animation sets, multiple gate variants, dense prop packs, or new fullscreen backgrounds.

## Non-Claims

- V3B assets are runtime candidates, not production-final art.
- This task does not recompress or replace art.
- No composite/reference sheet is imported or cropped.
